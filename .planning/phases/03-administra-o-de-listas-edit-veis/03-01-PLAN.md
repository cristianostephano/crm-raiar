Entregar a espinha vertical da tela "Configurações": uma Supervisor navega até a tela protegida, vê a aba Categoria com a lista de valores existentes, e consegue **adicionar** um novo valor que aparece na hora — refletindo também no dropdown de categoria do cadastro de cliente. </objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Vendedor (autenticado, não-supervisor) → /configuracoes + Server Actions de listas + tabelas de lookup | Entrada não confiável tenta escrever nas listas contornando a UI escondida/redirect |
| Client → input `nome` da Server Action | Texto arbitrário do cliente cruza para o servidor |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Elevation of Privilege | createListaValor / tabelas de lookup | high | mitigate | RLS INSERT Supervisor-only (`is_supervisor()`, migração 0002 linhas 213-243) é o limite real, PROVADO pela Task 1 como Vendedor; defense-in-depth: createListaValor rejeita não-Supervisor com "forbidden" antes do insert (espelha deleteCliente) |
| T-03-02 | Tampering | input `nome` da Server Action | medium | mitigate | Re-validação server-side com createListaValorSchema (min(1)); constraint unique(nome) já existente rejeita duplicado (23505 -> erro estruturado não-revelador) |
| T-03-03 | Information Disclosure | rota /configuracoes | low | mitigate | Redirect server-side por profiles.role antes de render (espelha equipe/page.tsx); SELECT das lookup já é aberto a todo autenticado (dropdowns), então não há dado sensível exposto — o lado de escrita é o limite |
| T-03-SC | Tampering (supply chain) | dependências | low | accept | Nenhuma instalação npm/pip/cargo neste plano (sem novo pacote runtime). Sem gate de legitimidade aplicável |
