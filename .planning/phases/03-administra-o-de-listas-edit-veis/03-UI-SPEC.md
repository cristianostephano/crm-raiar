# Phase 3 — UI Design Contract

> Visual and interaction contract for "Configurações" (Supervisor-only): a single tabbed screen managing the 4 editable lookup lists — Categoria, Produtos consumidos, Tipos de tarefa, Motivos de perda (ADM-01..04). This phase INHERITS the design-system foundation locked in `01-UI-SPEC.md` and extended in `02-UI-SPEC.md` — shadcn `nova` preset, blue-only accent, 8-point spacing, 4-size/2-weight typography. Nothing in that foundation is re-decided here. This is a small, low-novelty phase: one new interaction pattern (editable list row) applied identically across 4 tabs, reusing components already installed. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Spacing Scale

Inherited unchanged from Phase 1/2 (multiples of 4): `xs 4px / sm 8px / md 16px / lg 24px / xl 32px / 2xl 48px / 3xl 64px`.

Exceptions added this phase:

| Exception | Value | Reason |
|-----------|-------|--------|
| List row height (each value in a tab's list) | 44px min-height | Matches the WCAG touch-target precedent already used for icon-only controls in Phases 1-2 (password-eye toggle, kanban quick-action icons) — every row has 2-3 tap targets (edit, deactivate/reactivate), so the row itself must clear 44px even though its text content is smaller |
| Gap between list rows | `xs` (4px) via a 1px border between rows (not a gap) | Rows read as one connected list (like "Gerenciar equipe"'s table), not as separated cards — matches the existing table's `border-t` per-row pattern |
| "Adicionar novo valor" inline form padding | `md` (16px) | Matches the card padding used for the "gerenciar equipe" invite section (Phase 1) |
| Tab content top padding | `lg` (24px) | Separates the tab strip from the list below, consistent with Phase 2's toolbar-to-tabs spacing |

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (white / `oklch(0.145 0 0)` dark) | Page background behind the "Configurações" content area |
| Secondary (30%) | `--secondary` (light gray `oklch(0.97 0 0)`) / `--card` (white) | List container border/background, tab strip underline area — matches "Gerenciar equipe"'s table container styling exactly |
| Accent (10%) | `--primary` blue (`oklch(0.546 0.215 262.881)` light / `oklch(0.623 0.188 259.815)` dark) | Reserved for: the active tab indicator, the "Adicionar" primary button (one per tab), the per-row "Salvar" button that appears only while a row is in inline-edit mode, and focus rings. **Never** used for: the "Desativar"/"Reativar" row actions (these are neutral/ghost, not accent — deactivating is not a primary action), the "Inativo" badge, or table header text |
| Destructive | `--destructive` red (`oklch(0.577 0.245 27.325)` light / `oklch(0.704 0.191 22.216)` dark) | Reserved for: inline validation error text (e.g. duplicate value name) only. Explicitly NOT used for "Desativar" (per D-03 this is a reversible soft-delete, not a destructive/irreversible action — using red here would overstate the risk and contradict the reassuring copy in the Copywriting Contract below) |

Accent reserved for: active tab indicator, "Adicionar" button (per tab), the row-level "Salvar" button shown only during inline edit, and input/button focus rings. Confirmed: at most one primary (blue-filled) button visible at rest per tab (the "Adicionar" button) — a second blue button ("Salvar") only appears transiently on the single row currently being edited, never two persistent blue buttons at once.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Page title | "Configurações" |
| Tabs (D-01, in this order) | "Categoria" / "Produtos consumidos" / "Tipos de tarefa" / "Motivos de perda" |
| Primary CTA — add new value (per tab, same pattern) | "Adicionar" (button), placeholder text in the input: "Nome da categoria" / "Nome do produto" / "Nome da tarefa" / "Nome do motivo" (swapped per active tab) |
| Row action — edit (D-04) | Ghost icon button, `Pencil` (lucide), `aria-label="Editar {valor}"` — click switches the row into inline-edit mode (`Input` replaces static text) with two icon buttons: `Check` ("Salvar", `--primary`) and `X` ("Cancelar", ghost/neutral) |
| Row action — deactivate (D-03) | Ghost icon button, `EyeOff` (lucide) — NOT `Trash2`, deliberately avoiding a trash-can icon since nothing is deleted (D-03); `aria-label="Desativar {valor}"` |
| Row action — reactivate (Claude's discretion — see Screen-Specific Notes) | Ghost icon button, `Eye` (lucide), shown only on inactive rows when "Mostrar inativos" is on; `aria-label="Reativar {valor}"` |
| Confirmation — deactivate (D-03, low-friction since reversible) | `Dialog`: "Desativar \"{valor}\"?" + body: "Esse valor deixa de aparecer para novos cadastros, mas continua normalmente nos clientes que já usam \"{valor}\". Você pode reativar quando quiser." Buttons: "Cancelar" (ghost) / "Desativar" (neutral/secondary-filled, NOT `--destructive` — matches the Color contract's reasoning that this is not a destructive action) |
| Toggle — show inactive values | `Switch` label: "Mostrar inativos" — OFF by default per tab (matches D-01's spirit of a clean list of currently-usable values; inactive values are opt-in visibility, not hidden-forever) |
| "Inativo" badge label | "Inativo" (neutral/outline `Badge`, same visual treatment as Phase 2's "Incompleto" badge — never blue, never red) |
| Empty state — a tab with zero active values (e.g. right after every value in it was deactivated) | Heading: "Nenhum valor ativo nesta lista." Body: "Adicione um novo valor acima, ou ative \"Mostrar inativos\" para ver os valores desativados." |
| Error — duplicate name on add or edit | "Já existe um valor chamado \"{nome}\" nesta lista." |
| Error — empty name on add | "Digite um nome antes de adicionar." |
| Error — generic save failure | "Não foi possível salvar. Tente novamente." |
| Success — value added | "\"{valor}\" adicionado." |
| Success — value edited | "\"{valor}\" atualizado." |
| Success — value deactivated | "\"{valor}\" desativado." |
| Success — value reactivated | "\"{valor}\" reativado." |
| Access-denied note (for the researcher/checker only — no visible copy since the route redirects, per D-02/ADM-05) | Not applicable — a Vendedor never sees a broken/disabled version of this screen; the route itself redirects to "/", identical to the "Gerenciar equipe" pattern from Phase 1 |

## Screen-Specific Notes

### Configurações (`app/(app)/configuracoes/page.tsx`, Supervisor-only, D-02)

- Same Supervisor-only route-protection pattern as `app/(app)/equipe/page.tsx` (Phase 1): server-side check of `profiles.role`, redirect non-Supervisors to `/` before rendering anything — this is the real ADM-05 boundary alongside RLS write policies on the 4 lookup tables (per `supabase-conventions` skill); the app-layer redirect is UX only.
- Nav entry: "Configurações" link, visible only when the logged-in profile's role is `supervisor` — same visibility pattern already used for "Gerenciar equipe".
- Page-level Display heading "Configurações" (28px/600), top-left, no primary action button beside it (unlike "Gerenciar equipe" and "Clientes" — the primary action here is per-tab "Adicionar", not page-level).
- `Tabs` (D-01) directly below the heading: "Categoria" / "Produtos consumidos" / "Tipos de tarefa" / "Motivos de perda", in that order — mirrors the domain's own conceptual order (client attributes first, then funnel-related lists). Active tab indicator uses `--primary` blue underline, same as Phase 2's "Todos"/"Incompletos" tabs.
- Each tab's content (identical structure across all 4 — one shared component, e.g. `EditableListTab`, parameterized by table name/labels):
  - Row count caption, e.g. "4 categorias ativas" (14px/400, muted-foreground), plus the "Mostrar inativos" `Switch` (Claude's discretion addition, right-aligned on the same row).
  - The list itself: a bordered container identical in visual treatment to "Gerenciar equipe"'s table (`rounded-lg border`, `--secondary` background not needed here since there's only one column of real content — a plain `divide-y` list of rows is enough, simpler than a multi-column table).
  - Each row (44px min-height, `px-4` horizontal padding matching the table's `px-4`):
    - At rest: value name (Body, 16px/400) left-aligned; if inactive, name renders at `muted-foreground` opacity with an "Inativo" badge immediately after it; right-aligned: `Pencil` (edit) + `EyeOff` (deactivate) ghost icon buttons for active rows, or just `Eye` (reactivate) for inactive rows (shown only when "Mostrar inativos" is on).
    - In edit mode (triggered by `Pencil`, D-04): the name renders as an `Input` (same row height preserved) pre-filled with the current value; right-aligned icon buttons switch to `Check` (Salvar, `--primary`) and `X` (Cancelar, ghost) — pressing Enter in the input also submits, Escape cancels.
    - Deactivating (`EyeOff`) opens the low-friction `Dialog` from the Copywriting Contract above — confirms the action without alarming destructive-red styling, since D-03 guarantees nothing is lost.
  - Bottom of the list (or top — Claude's discretion, top preferred so "Adicionar" is immediately visible without scrolling past existing values): inline "Adicionar novo valor" form — a single `Input` (placeholder swapped per tab, per Copywriting Contract) + "Adicionar" primary button (`--primary` filled) inline to its right. Enter key in the input also submits. On success, the new row appends to the list (active by default) and the input clears, ready for the next entry — supports adding several values back-to-back with minimal friction, consistent with the project's "mínimo de fricção" core value.
  - Empty state (all values in this tab deactivated and "Mostrar inativos" is off — an edge case, not the common path): per Copywriting Contract above, centered in the list area, "Adicionar" form remains visible above it.
- Every change (add/edit/deactivate/reactivate) reflects immediately in the dropdowns/checklists that read these tables elsewhere in the app (`ClienteQuickCreateForm`, `ClienteDetailSheet`, `PerdaMotivoDialog`, task-type selector) because those already query the same `ativo = true` rows live from the DB — no caching layer to invalidate, per the CONTEXT.md Integration Points note.
