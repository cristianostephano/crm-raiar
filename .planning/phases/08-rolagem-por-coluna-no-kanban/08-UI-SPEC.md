## Component-Specific Implementation Notes

*(Extends the template — this phase's actual contract lives mostly here, since it's a layout/interaction change to one existing component rather than a new visual surface. Both render branches of `KanbanBoard.tsx` — the `dragDisabled` static branch (~L637–675) and the `DndContext`-wrapped draggable branch (~L677–726) — must receive the identical structural change below, so KAN-01/KAN-02 hold regardless of whether search/filter/sort is active.)*

### 1. Column height formula (D-02)

Apply the fixed height to the **column's card-list container** (the droppable boundary — see §2), not to the outer `w-[280px]` column wrapper and not to the header:

```
h-[calc(100vh-300px)] min-h-[360px]
```

- `calc(100vh - 300px)`: 300px is the measured chrome above the columns row on `/clientes` today — page padding (`p-6` top, 24px) + `<h1>`/"Novo cliente" row (~40px) + `gap-8` (32px) + "Exportar" button row (~40px) + `gap-4` (16px) + `ClienteToolbar` (~110px, `bg-secondary p-3` with two stacked rows) + `gap-4` (16px) + a small safety margin so the column's bottom edge (plus the page's bottom `p-6` padding) doesn't itself force the outer page to scroll. This value is calibrated against the current `page.tsx`/`KanbanBoard.tsx` markup — **verify visually against a real render during implementation and nudge the constant if the toolbar wraps to a different number of rows** (e.g. narrow viewport, long team name in a filter chip); the formula shape (`100vh - constant`), not the exact `300`, is the contract.
- `min-h-[360px]`: floor so the column never becomes so short it can't "still show the cards properly" (D-02) — enough vertical room for the column header plus roughly 2-3 `ClienteCard`s before the internal scroll takes over, even on a very short/laptop-with-devtools-open viewport.
- All 7 columns use the same class (they already share `ETAPAS.map`), so KAN-02 ("todas as colunas têm a mesma altura, cheias ou vazias") is satisfied automatically — do not compute per-column height from card count.

### 2. Header stays visible while the list scrolls (Success Criterion 3)

Do **not** use `position: sticky` — instead keep the DOM structure that already separates header from body and only make the body scroll:

```
<div className="flex w-[280px] shrink-0 flex-col gap-2">   {/* unchanged outer column wrapper */}
  <div className="flex items-start gap-2 rounded-lg bg-secondary px-3 py-2"> {/* unchanged header — stays OUTSIDE the scroll container, so it can't scroll away */}
    ...title + count badge...
  </div>

  <div ref={setNodeRef} className="relative flex h-[calc(100vh-300px)] min-h-[360px] flex-col"> {/* NEW: fixed-height droppable boundary, itself does NOT scroll */}
    <div className="min-h-0 flex-1 overflow-y-auto flex flex-col gap-2"> {/* NEW: this is the ONLY element that scrolls */}
      ...cards (or empty-state text)...
    </div>
    {/* fade indicator, see §3, absolutely positioned inside the droppable boundary */}
  </div>
</div>
```

`min-h-0` on the inner scrollable div is required — a flex child's default `min-height: auto` otherwise prevents it from shrinking below its content size, which silently defeats `overflow-y-auto` (classic flexbox-scroll gotcha).

### 3. Bottom scroll-fade indicator (D-03)

- Structure: an absolutely-positioned sibling `div` inside the fixed-height droppable boundary (§2), not inside the scrolling inner div itself (so it stays pinned to the bottom of the column, not scrolling away with the content):
  `absolute inset-x-0 bottom-0 h-6 bg-gradient-to-t from-background to-transparent pointer-events-none transition-opacity duration-150 ease-out aria-hidden="true"`
- Height: `h-6` (24px, the `lg` spacing token).
- Color: `from-background` (the Dominant/60% surface color the cards actually sit on) — never `from-secondary` (that's the header's color, not the list body's) and never a primary/accent color.
- Visibility: **conditional**, not always-rendered — only shown when the column's inner scroll container has more content below the fold (`scrollHeight - scrollTop - clientHeight > 1`). Compute this per-column with a `scroll` + resize-aware check (e.g. a small `onScroll` handler plus a check on mount/card-count-change), toggling `opacity-100` vs `opacity-0` — do not add a second always-on layer that would visually clip content in short/near-empty columns. This satisfies D-03's "quando tem mais conteúdo pra rolar" condition instead of always showing a fade even on a column with 1 card.
- `pointer-events-none` is mandatory so the fade never blocks drag/drop or click-to-open interactions on the last visible card.

### 4. Drag-and-drop must keep working with the new scroll containers (Success Criterion 4, Pitfall 12)

Applies only to the `DndContext`-wrapped branch (~L677–726); the `dragDisabled` static branch needs §1–§3 only, no dnd-kit changes.

- **Measuring strategy:** add `measuring={{ droppable: { strategy: MeasuringStrategy.Always } }}` to the existing `<DndContext id="clientes-kanban" sensors={sensors} collisionDetection={closestCenter} onDragEnd={handleDragEnd}>`. Import `MeasuringStrategy` from `@dnd-kit/core`. Without this, dnd-kit measures droppable rects once at drag start and won't re-measure as a column auto-scrolls during a drag, causing drops to register in the wrong slot.
- **Droppable boundary vs. scrollable list must be different elements:** `useDroppable`'s `setNodeRef` goes on the *outer* fixed-height container (§2's `h-[calc(100vh-300px)]` div), not on the inner `overflow-y-auto` div — this matches Pitfall 12's guidance to keep the drop-zone rect stable and separate from the element that actually scrolls.
- **`DragOverlay` must keep portaling to `document.body`** (dnd-kit's default) — do not nest it inside the new scroll container, or the column's `overflow-y-auto`/`h-[calc(...)]` will visually clip the dragged card the moment it's lifted above the column's bounds.
- **Manual verification required before calling this phase done:** drag a card from the top to the bottom of a column that has more cards than fit in `h-[calc(100vh-300px)]`, confirming (a) auto-scroll engages as the pointer nears the column's bottom edge, and (b) the card drops into the correct position, not the wrong slot.

### 5. Empty columns (Success Criterion 2)

An empty column still renders the fixed-height droppable boundary (§1/§2) at full height — do not conditionally shrink it when `clientes.length === 0`. The existing "Nenhum cliente nesta etapa" text renders inside the now-scrollable (but non-overflowing) inner div exactly as today; the column's outer height stays identical to every sibling column regardless of card count.
