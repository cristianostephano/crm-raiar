# Phase 2 — UI Design Contract

> Visual and interaction contract for Cadastro e Funil de Vendas: the client list/kanban board (7 fixed pipeline stages), the client create/edit experience (quick-create + full detail), and the "Incompletos" filter tab. This phase INHERITS the design-system foundation locked in `01-UI-SPEC.md` (Phase 1) — shadcn `nova` preset, blue-only accent, 8-point spacing, 4-size/2-weight typography. Nothing in that foundation is re-decided here; this contract only adds what Phase 2's screens need on top of it. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

| Property | Value |

**Color decision:** inherited unchanged from Phase 1 — blue (`--primary`) is the single accent, reserved for actionable/selected elements only. This phase adds two new **status-only** semantic colors (see Color section below) because the funnel introduces business outcomes (ganho/perdido/atrasado) that Phase 1's palette (neutral + blue + red) has no room to express without overloading `--destructive` or breaking the "blue never used for status badges" rule already locked in `01-UI-SPEC.md`.

## Spacing Scale

Inherited unchanged from Phase 1 (multiples of 4): `xs 4px / sm 8px / md 16px / lg 24px / xl 32px / 2xl 48px / 3xl 64px`.

Exceptions added this phase:

| Exception | Value | Reason |
|-----------|-------|--------|
| Kanban card padding | `sm` (8px) all sides, not `md` | D-03 requires a compact card so "vários clientes visíveis por tela" — using `md` padding would cut visible cards per screen roughly in half |
| Kanban column min-width | 280px (not a spacing token — layout constraint) | Keeps company name + badges readable without wrapping awkwardly; board scrolls horizontally below 7×280px on smaller screens |
| Gap between kanban columns | `md` (16px) | Enough visual separation between stages without wasting horizontal space across 7 columns |
| Gap between cards within a column | `sm` (8px) | Matches the compact-density intent of D-03 |
| Quick-action icon buttons (phone/WhatsApp/calendar on card) | 44px touch target, ~28px visual icon | Same accessibility exception as Phase 1's password-eye toggle — small visual footprint to stay compact, full touch target for mobile tap accuracy (WCAG minimum), the entire card itself also remains the drag handle so this never conflicts with drag-and-drop |
| Client detail drawer (`Sheet`) width | 480px desktop, full-width mobile | Wide enough to hold both "Dados do cliente" and "Funil" sections without cramming, without going full-screen and losing the kanban context behind it |
| Quick-create `Dialog` max-width | 420px | Consistent with Phase 1's 400px auth-card motif, +20px to fit the 2-column endereço grid |

## Typography

Inherited exactly from Phase 1 — **do not add a 5th size or 3rd weight.** Only new size/weight *combinations* using the same 4 sizes (14/16/20/28) and 2 weights (400/600) are introduced below.

| Role | Size | Weight | Line Height | Notes |
|------|------|--------|-------------|-------|
| Body | 16px | 400 | 1.5 | Form field values, dialog/drawer body copy — same as Phase 1 |
| Label | 14px | 600 | 1.5 | Field labels, column headers' secondary text — same as Phase 1 |
| Heading | 20px | 600 | 1.2 | Kanban column titles, "Dados do cliente" / "Funil" section titles inside the drawer, quick-create dialog title |
| Display | 28px | 600 | 1.2 | Page-level title "Clientes" at the top of the list/kanban screen |
| **Card title (new combo)** | 16px | **600** | 1.3 | Razão social on a compact kanban card — needs to read as "prominent" per D-04/D-03's screenshot reference, but a full Heading (20px) would break card compactness, so it reuses Body's size at Label's weight — still within the declared 4×2 inventory |
| Meta/help text (precedented in Phase 1) | 14px | 400 | 1.4 | Card secondary info (categoria, vendedor name, column count), histórico timeline entries, overdue/error captions |

## Color

Inherited base roles unchanged from Phase 1 (`--background`, `--card`/`--secondary`, `--primary` blue, `--destructive` red). This phase adds two **status-only** tokens, used exclusively on badges/highlights for funnel business states — never on buttons, never as a section background, per the same discipline Phase 1 applied to blue.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (white / `oklch(0.145 0 0)` dark) | Page background behind the kanban board and behind the client detail drawer |
| Secondary (30%) | `--secondary` (light gray `oklch(0.97 0 0)`) / `--card` (white) | Kanban column header panels, card surfaces, top toolbar background, filters popover surface |
| Accent (10%) | `--primary` blue (`oklch(0.546 0.215 262.881)` light / `oklch(0.623 0.188 259.815)` dark) | Reserved for: the "Novo cliente" primary button, the "Salvar" button in the client detail drawer, the "Cadastrar cliente" button in quick-create, the active "Todos"/"Incompletos" tab indicator, focus rings, the checked state of task checkboxes, and a small active-state dot on the "Filtros" button when ≥1 filter is applied. **Never** used for: status badges (em andamento/ganho/perdido), the "Incompleto" badge, the overdue highlight, or the categoria/produto badges on a card |
| Destructive | `--destructive` red (`oklch(0.577 0.245 27.325)` light / `oklch(0.704 0.191 22.216)` dark) | "Apagar cliente" button + its confirmation dialog, the "perdido" status badge, the "Confirmar perda" button inside the perdido-motivo modal, overdue task due-dates (text color only, not the card highlight itself — see Warning below), inline validation errors |
| **Success (new, status-only)** | approx. Tailwind `green-600` `oklch(0.627 0.194 149.214)` light / `green-500` `oklch(0.723 0.219 149.579)` dark | Exclusively the "ganho" status badge on a card and in the status selector. Never a button color, never a background fill larger than a badge |
| **Warning (new, status-only)** | approx. Tailwind `amber-500` `oklch(0.769 0.188 70.08)` light / `amber-400` `oklch(0.828 0.189 84.429)` dark | Exclusively the "parado/atrasado" visual highlight on a kanban card (4px left border + small `TriangleAlert` icon with tooltip) — required by FUN-09. Never a button color |

Accent reserved for: "Novo cliente" button, "Salvar" button (client drawer), "Cadastrar cliente" button (quick-create), active tab indicator, input/button focus rings, checked task-checkboxes, and the "Filtros" active-state dot. Confirmed: at most one primary (blue-filled) button visible per screen — the drawer's "Salvar" and the "+ Adicionar tarefa" button never compete, since "+ Adicionar tarefa" is outline/ghost, not filled blue.

## Screen-Specific Notes

### Client List / Kanban Board (`app/(app)/clientes/page.tsx`) — primary screen this phase

- Page-level Display heading "Clientes" (28px/600), top-left.
- Toolbar row directly below the heading, on a `--secondary` panel background: search `Input` (icon-prefixed, placeholder "Buscar por razão social...", filters only by razão social per D-07), "Filtros" outline button (opens a `Popover` per Claude's discretion in CONTEXT.md — contains Vendedor/responsável `Select` [Supervisor-only, D-09], Categoria `Select`, Produto consumido multi-select checklist, Cidade `Input`, Estado `Select`; footer buttons "Limpar filtros" / "Aplicar filtros"), "Ordenar por" `DropdownMenu`, and the primary "Novo cliente" button (`--primary` filled) right-aligned — this is the one blue button on this screen.
- `Tabs` directly below the toolbar: "Todos" (default) / "Incompletos" (D-01 — no separate screen, just a filtered view of the same list). Active tab indicator uses `--primary` blue underline (permitted "active state" use).
- Below the tabs: the kanban board — 7 fixed columns (D-05), horizontally scrollable as a set below viewport width. Each column header: etapa name (Heading, 20px/600) + count badge (neutral/outline, 14px/400) on a `--secondary` panel.
- Card anatomy (compact, D-03/D-04), `sm` (8px) padding, `sm` (8px) vertical gap between cards:
  - Razão social — Card title role (16px/600), truncated to 1 line.
  - Categoria badge — neutral/outline `Badge`, 14px/400 (never blue).
  - Vendedor/responsável name — 14px/400, muted-foreground, **Supervisor view only** (a Vendedor already knows every card is theirs, per CLI-04, so this line is omitted for Vendedor to keep the card denser).
  - "Incompleto" badge (D-02) — neutral/outline, top-right corner of the card, shown only when any optional field is blank.
  - Overdue/stale highlight (FUN-09) — 4px `Warning` amber left border + small `TriangleAlert` (lucide) icon with tooltip, computed and shown as soon as the kanban screen opens (no interaction needed to reveal it).
  - Quick-action icon row (bottom of card) — ghost icon buttons for phone (`Phone`), WhatsApp/message (`MessageCircle`), and schedule (`CalendarClock`) lucide icons, muted-foreground color, 44px touch target/~28px visual size. These are informational shortcuts (e.g. `tel:`/`https://wa.me/` links using the client's `telefone`) — not part of FUN scope beyond D-03's visual inspiration; if the phone/WhatsApp fields are blank, the icon renders disabled/muted, not hidden (keeps card layout stable).
  - The entire card is the drag handle (dnd-kit `useDraggable`), keyboard-operable per the stack's accessibility requirement — clicking (not dragging) opens the detail `Sheet`.
- Empty states: per Copywriting Contract above, centered in the affected column or list area.

### Client Detail / Edit (`Sheet`, opened by clicking any card or any row in "Incompletos")

- Right-side `Sheet`, 480px desktop / full-width mobile. Header: razão social as the sheet title (Heading, 20px/600) + close (X) +, **Supervisor only**, an "Apagar cliente" ghost `--destructive`-colored button (CLI-05/06 — never rendered for Vendedor, enforced server-side by RLS as the real boundary, per the Phase 1 pattern).
- Section 1 — "Dados do cliente" (Heading, 20px/600, `Separator` below):
  - Required (always editable): Razão social, Endereço (CEP, rua, número, complemento, cidade, estado — D-11), Responsável (`Select`, Supervisor can reassign per CLI-03; Vendedor sees own name, read-only, per CLI-04).
  - Optional (CLI-02): Categoria `Select`, Contato `Input`, Telefone `Input`, Email `Input`, Produtos consumidos (multi-select checklist), Número de lojas `Input` (numeric).
- Section 2 — "Funil" (Heading, 20px/600, `Separator` above):
  - Status `Select`: "Em andamento" (default, neutral badge) / "Perdido" (red badge; selecting it opens the "Confirmar perda" modal requiring `motivo`, FUN-06) / "Ganho" (green badge; **disabled** with the Copywriting Contract's tooltip unless the card's current etapa is "1ª venda concluída", FUN-05 — this is a UI-level courtesy only, the real enforcement is a DB constraint/RLS check per the `supabase-conventions` skill).
  - Observação — `Textarea`, free text (FUN-07).
  - Tarefas — checklist (FUN-08): each row = `Checkbox` (checked state uses `--primary` blue fill, an allowed "selected state" use) + tarefa tipo (14px/400) + `data_conclusao` via `Calendar`-backed `Popover` date picker (red 14px/400 text if the date has passed and the task is unchecked) + ghost delete icon. "+ Adicionar tarefa" outline button below the list (not filled blue — keeps "Salvar" the only primary action on this screen).
  - Histórico — read-only vertical timeline (FUN-10): each entry = timestamp (14px/400, muted-foreground) + plain-language change description (14px/400, foreground), e.g. "16/07/2026 14:32 — Etapa alterada para \"Conversa realizada com comprador(a)\"." No color coding, no icons — kept deliberately plain since it's an automatic, non-interactive log.
- Footer: "Salvar" primary button (`--primary` filled), pinned to the bottom of the `Sheet`.

### Quick-Create (`Dialog`, triggered by "Novo cliente")

- `Dialog`, max-width 420px, title "Novo cliente" (Heading, 20px/600).
- Only the 3 required fields (CLI-01): Razão social (`Input`), Endereço as a compact 2-column grid (CEP + número on one row; rua full-width; complemento + cidade + estado on a following row), Responsável (`Select` — Vendedor: pre-filled with own name, disabled; Supervisor: must choose explicitly, no default pre-selected, mirroring Phase 1's D-05 "no default role pre-selected" pattern for the invite form, per CLI-03).
- Primary "Cadastrar cliente" button, full dialog width, `--primary` filled — the only blue element in this dialog.
- Helper caption below the button (muted-foreground, 14px/400): "Você pode completar os demais dados depois, na tela do cliente." — reinforces D-01/D-02's incremental-completion model at the exact moment friction would otherwise creep in.
- On success: dialog closes, success toast ("Cliente cadastrado com sucesso."), new card appears in the "Aguardando contato" column (the funnel's first stage) — this is also the origin point of every client's kanban lifecycle, so no separate "assign initial stage" control is needed.
