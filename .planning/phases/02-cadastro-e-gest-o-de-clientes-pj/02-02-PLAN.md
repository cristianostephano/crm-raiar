## Phase Goal
**As a** vendedor, **I want to** cadastrar um cliente PJ em segundos informando só razão social, endereço e responsável, **so that** eu pare de abandonar o CRM por causa de telas longas e consiga completar o resto depois.

This is the phase's first end-to-end slice: create a client with the three required fields and immediately see its card land in the first funnel stage. It proves the whole stack (auth → RLS → Server Action → DB → Server Component render) works for `clientes`, exactly as 01-04's invite flow proved it for `profiles`.

Purpose: Deliver the friction-killer that motivated the whole project — minimal-required-field creation (CLI-01), everything else deferrable (CLI-02), Supervisor can assign the responsável (CLI-03).

<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| browser Client Component → createCliente Server Action | Untrusted form input crosses into the server; the action must re-validate and must not trust a client-supplied responsavel for a Vendedor. |
| Server Component → PostgREST | RLS scopes which clientes render; no manual responsavel filter in app code. |

## STRIDE Threat Register
| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-07 | Tampering | createCliente input | medium | mitigate | Server Action re-validates with createClienteSchema (never trusts the client-side validation) and forces responsavel = caller uid for Vendedores. |
| T-02-08 | Elevation of Privilege | responsavel assignment | high | mitigate | Only a Supervisor may set responsavel to another user; enforced in the action AND by the clientes INSERT/UPDATE RLS from 02-01. |
| T-02-09 | Information Disclosure | /clientes list | high | mitigate | Server Component read is RLS-scoped; a Vendedor's page can only render their own rows even though the query has no explicit filter. |
| T-02-10 | Spoofing | duplicate-error copy | low | accept | D-06 error message deliberately does not reveal which vendedor owns the existing razão social (UI-SPEC copy). |
</threat_model>
