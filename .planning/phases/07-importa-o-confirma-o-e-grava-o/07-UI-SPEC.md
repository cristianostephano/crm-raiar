## Typography

Inherits the project's locked 4-size scale (14px body / 12px label / 16px heading / 20px display, two weights: 400 regular + 600 semibold) — see `06-UI-SPEC.md` for the full table, unchanged.

**No new size is introduced this phase.** The two summary-tile numbers use the existing 20px display size (`text-xl`) — the largest size already in the project's locked 4-size scale — not the Dashboard's 36px stat-number waiver (`GanhosPerdidosCards.tsx`). That waiver's own text (`04-UI-SPEC.md`) scopes it explicitly to the Dashboard's 3 original KPI tiles only, marks it non-precedential, and states verbatim "do not reuse it anywhere else" — so it does not apply here regardless of the visual similarity between this screen's tiles and the Dashboard's tiles. No fresh owner waiver was requested; these two elements simply fit inside the existing approved scale:

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Stat number | 20px (`text-xl`, existing display size) | 600 (semibold) | 1.2 (existing display line-height, per `06-UI-SPEC.md`) | The two summary tiles' counts ("Clientes importados", "Linhas puladas") |
| Stat tile label | 14px (`text-sm`), semibold | 600 | 1.5 | "Clientes importados" / "Linhas puladas" tile labels, paired with their icon |

All other text on this screen (heading, breakdown list, buttons) uses the existing 4-size scale unchanged. The spec now uses exactly 4 font sizes project-wide (12/14/16/20px) — no 5th size.

## Copywriting Contract

### Confirm action (Review screen, existing button — this phase wires it)

| Element | Copy |
|---------|------|
| Button label, idle | Confirmar importação (unchanged from Phase 6) |
| Button label, in flight | Importando clientes… (button disabled, same text-swap pattern as `EditableListTab.tsx`'s `disabled={isReactivating}` reactivate button — no separate spinner component) |
| Destructive confirmation | **None.** Clicking "Confirmar importação" is itself the single required confirmation — the Supervisor has already reviewed every row status in Step 3 and made every duplicado decision explicitly. Precedent: Phase 3's reactivate action also has no confirmation dialog (only the genuinely irreversible deactivate does); this write is additive (creates clients) with no destructive/irreversible side effect on existing data, so an extra "Tem certeza?" dialog would only add friction against the project's core value ("mínimo de fricção possível"). The actual double-submit guard is the disabled+relabeled button while the request is in flight, not a dialog. |

### Summary screen (new — D-01)

| Element | Copy |
|---------|------|
| Screen heading | Importação concluída |
| Stat tile 1 label | Clientes importados |
| Stat tile 2 label | Linhas puladas |
| Breakdown section heading (only rendered when puladas > 0) | Motivos das linhas puladas |
| Breakdown line — per erro reason (grouped, reuses Phase 6's exact reason vocabulary) | {motivo} — {N} linha(s) — e.g. "Razão social não informada — 3 linhas" |
| Breakdown line — duplicado skipped in Step 3 | Possível duplicado (pulado na revisão) — {N} linha(s) |

### Error states (new this phase)

| Element | Copy |
|---------|------|
| Confirm call fails entirely (no RPC ran, nothing written — e.g. network/auth failure before the RPC) | Não foi possível concluir a importação agora. Nenhum cliente foi criado. Tente novamente. |
| (Reuses existing `role="alert"` destructive-tinted banner styling from Phase 6/`EditableListTab.tsx` — same markup, new copy string, same `VALIDATION_ERROR`-style top-of-file constant convention) | — |

## Layout & Interaction Notes (Claude's Discretion resolved)

`07-CONTEXT.md` left the exact summary-screen layout ("lista detalhada por linha vs. só contagem agregada") to Claude's Discretion — resolved here:

- **Decision: aggregated by reason, not a re-rendered per-row table.** The Supervisor already reviewed every row individually in Step 3 (`ImportPreviewTable`). Per D-03, skipped rows are never persisted — they exist only for this one operation's summary. Re-listing every skipped row a second time would duplicate a table the Supervisor just saw with no new information; a reason-grouped count answers "why were things skipped" completely and scans faster for a possibly-large batch. If a specific batch's skip count is large, the grouped list still reads in a few lines instead of scrolling a second full table.
- **Replaces the wizard body; step indicator (1/2/3) is hidden.** On confirm success, swap `ImportWizard`'s rendered body for the summary view. The numbered step row ("1 Enviar planilha · 2 Mapear colunas · 3 Revisar") no longer applies once the operation is complete — do not leave "3 Revisar" highlighted underneath a finished summary.
- **Stat tiles:** two-column grid (`grid grid-cols-1 gap-4 md:grid-cols-2` — same responsive breakpoint as `GanhosPerdidosCards`' three-column grid, just two tiles instead of three), each a `Card` with `border-l-4` in the color assigned above, containing `CardContent className="flex flex-col gap-2 p-6"` with an icon+label row (`text-sm font-semibold text-muted-foreground`, icon `size-4 text-muted-foreground`) above the `text-xl leading-[1.2] font-semibold text-foreground` count — same border/icon/label layout as `GanhosPerdidosCards.tsx`'s tile, but the number itself uses this project's locked 20px display size (`text-xl`), not that component's 36px waiver.
- **Primary visual focal point:** the "Clientes importados" tile's number is the first thing the eye lands on — it is the left-most tile, carries the (new) green success border plus the `CircleCheck` icon, and answers the question the Supervisor opens this screen to ask ("did it work, and how many"). The "Linhas puladas" tile and the breakdown list are deliberately secondary/quieter (amber border, muted list text) so they read as supporting detail rather than competing for attention.
- **Breakdown list:** plain `<ul>`/`<li>` (not a `Table` — this is a short list, not tabular data with columns), `text-sm text-muted-foreground`, one line per distinct reason string with its count, directly below the tiles. Omit the whole section when there are zero skipped rows.
- **Buttons row:** `flex gap-2`, "Ver clientes" first (`Button` default variant — the only accent-blue element on this screen) then "Importar outra planilha" (`Button variant="outline"`) — same two-button row shape already used for Voltar/Continuar throughout the wizard, just different copy/destination.
  - "Ver clientes" navigates to the existing kanban route (`/clientes`) — new clients are already visible there in "Aguardando contato" per IMP-09/the Phase 7 goal.
  - "Importar outra planilha" resets the wizard to Step 1 (same state reset already implemented in `handleRemoveFile` — file, parsed, mapping, mappedRows, validatedRows, plus the new confirm-result state — back to their initial values, `setStep(1)`).
- **In-flight state:** while `confirmarLoteImportacao` is running, disable "Confirmar importação" and relabel it "Importando clientes…" (matches the existing `disabled={!validatedRows}` button, extended with an `isConfirming` flag) — do not use a full-panel `Skeleton` replacement here, since the Review table stays visible and interactive-looking is unnecessary once the Supervisor has already clicked confirm; a disabled relabeled button is sufficient feedback, consistent with `EditableListTab.tsx`'s reactivate-button precedent (not the parse/validate step's `Skeleton`-based loading treatment, which is for content that is about to change entirely).
- **Revalidation surfacing (D-02):** the confirm Server Action re-runs `findDuplicates`/`normalizeRazaoSocial` at write time. Any row that was `"ok"` in Step 3 but resolves as a new duplicate at confirm time must be excluded from the insert and counted under the distinct "Duplicado encontrado ao confirmar" breakdown line above — never silently folded into the generic erro count, per `07-CONTEXT.md`'s explicit instruction that "o resumo final deve refletir isso claramente pro supervisor."
