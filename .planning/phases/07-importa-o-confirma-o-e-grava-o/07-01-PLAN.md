<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller role → bulk-write feature | Any authenticated session can attempt `rpc('importar_clientes_lote')`; only a Supervisor may proceed |
| Server Action / client → RPC jsonb payload | `p_clientes` is untrusted data crossing into a DML statement |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Elevation of Privilege | importar_clientes_lote RPC | high | mitigate | `if not is_supervisor() then raise exception` as the first statement; RPC is not security definer so the clientes INSERT RLS policy from 0002 is the row-level backstop. Proven by Task 3 case 2 (vendedor rejected, zero rows written). |
| T-07-02 | Tampering / SQL injection | jsonb_to_recordset(p_clientes) | high | mitigate | Values arrive as a typed jsonb record set (parameterized rpc arg), never string-concatenated into SQL; no `execute`/dynamic SQL in the function. Column types (uuid/int) reject malformed values. |
| T-07-04 | Denial of Service / integrity (IMP-06) | set-based INSERT | medium | mitigate | Single set-based `INSERT ... ON CONFLICT DO NOTHING` (no plpgsql loop with per-row exception/savepoints, Pitfall A5/A6); a duplicate/conflicting row is skipped, never aborts the statement. Proven by Task 3 case 3. |
| T-07-05 | Tampering | responsavel uuid in payload | medium | accept | A Supervisor may legitimately assign any responsavel (CLI-03), and the clientes INSERT RLS allows it; an invalid uuid FK-fails the whole insert loudly (no silent corruption). Rows with unresolved responsavel are already erro-excluded upstream (07-02). Supervisor-only surface. |
| T-07-SC | Tampering (supply chain) | npm/pip/cargo installs | low | accept | No new package installs this phase — migration + test only; no Package Legitimacy Gate needed. |
</threat_model>
