## Component-Specific Implementation Notes

*(Extends the template — this phase's contract lives mostly here, since it governs the exact visual behavior of a brand-new table-shaped component and a small KPI-tile pair, both built entirely from primitives already proven elsewhere in this codebase.)*

### 0. Focal point

When at least one row is flagged `gargalo === true`, that row's amber-bordered "Gargalo" badge is the primary focal point of this whole new block — it's the one thing meant to catch the eye first. When no row is flagged, the `FunilDetalhadoTable` itself (as the first item in the new block, ahead of `TempoAteFechamentoCards`) is the entry point.

### 1. `FunilDetalhadoTable.tsx` — the D-01 table (FNL-01, 7 fixed rows)

**Card wrapper:** identical structure to `ClientesPorEtapaChart.tsx` — `Card` > `CardHeader` (`CardTitle` "Funil de conversão detalhado" at `text-[20px] font-semibold`, `CardDescription` "Histórico completo — não é afetado pelo filtro de período") > `CardContent` holding the `Table`.

**Row order:** always the 7 `ETAPAS` from `lib/funil/etapas.ts`, in that fixed array order — never re-sorted by any column value (matches `ClientesPorEtapaChart`'s `buildChartRows` "always render every etapa, even zero" precedent, extended to a table instead of a chart).

**Columns (5, in this exact order):**
1. **Etapa** — `ETAPAS[i].label` text, `font-medium` (matches `TableCell className="font-medium"` precedent from `ImportPreviewTable`'s "Razão social" column, i.e. the row's identifying column gets the emphasis weight, nothing else does)
2. **Quantidade** — historical "ever entered this stage" count (RESEARCH.md's recommended semantic, resolving Pitfall 5) + a small info icon (`CircleHelp` or reuse `TriangleAlert`-style inline icon, `size-3.5 text-muted-foreground`) wrapped in the existing `Tooltip` primitive carrying the clarification copy above. Do not add a second line of visible helper text under the number — the tooltip is the only disambiguation surface, keeping the cell visually identical in height to every other numeric cell.
3. **% Avançou** — `avancou_pct` formatted with the existing `percentFormatter` (`Intl.NumberFormat("pt-BR", {minimumFractionDigits:1, maximumFractionDigits:1})`, 1 decimal, e.g. "62,5%"), or "—" when null (quantidade is 0 for that stage).
4. **Perdidos** — combined format `"{perdidos_count} ({perdidos_pct}%)"` e.g. `"3 (12,5%)"`, both using the existing `integerFormatter`/`percentFormatter`; when perdidos_count is 0 render `"0"` alone (no `(0,0%)` suffix — matches the project's general instinct to not manufacture a fake percentage next to a genuine zero), when quantidade is 0 (nothing ever entered) render "—" for the whole cell.
5. **Tempo médio parado** — `"{tempo_medio_dias} dias"` (1 decimal via the same `percentFormatter`-style formatter) or "—" when null (no visits reconstructed for that stage yet). This cell also hosts the D-03 Gargalo badge when `gargalo === true` (see below).

**D-03 Bottleneck row highlight (never color-only):**
- Row background/border: `TableRow className="border-l-4 border-l-amber-500"` on any row where `gargalo === true` — reuses the exact `border-l-4 border-l-{color}-500` vocabulary already established by `statusBorderClass` in `lib/importacao/preview.ts` (there: green/amber/red for ok/duplicado/erro; here: amber only, since "gargalo" is a single boolean flag, not a 3-way status).
- Non-color signal (mandatory, do not skip): inside the "Tempo médio parado" cell, render a small pill next to the "{N} dias" text — `Badge variant="outline" className="gap-1 border-amber-500/40 text-amber-500"` containing `<TriangleAlert className="size-3" />` + the text "Gargalo". Same `amber-500` value in both light and dark mode — matches `ClienteCard.tsx`'s `text-amber-500` exactly, no separate dark-mode override invented (the codebase has no `amber-700` usage anywhere to justify one). This is the same icon (`TriangleAlert`, already imported project-wide for the "stuck" concept in `ClienteCard.tsx`/`ImportSummary.tsx`) reused for a new but visually-consistent purpose — never a bare color change with no icon/text, since that would fail for colorblind users comparing 7 rows.
- A non-bottleneck row renders with the default `TableRow` styling (no left border override, no badge) — the visual distinction must be present ONLY on flagged rows, never a subtler "everything is slightly colored" treatment.

**Loading state:** `Skeleton className="h-[320px] w-full"` inside `CardContent` (7-row table needs more vertical room than `ClientesPorEtapaChart`'s `h-[280px]` chart skeleton — scaled proportionally, still a single skeleton block, not per-row skeletons).

**Error state:** identical structure/copy to `ClientesPorEtapaChart`'s error branch — centered `flex h-[320px] w-full flex-col items-center justify-center gap-3 text-center` with the exact retry copy/button from the Copywriting Contract above, its own independent `reloadKey`/`FetchState` (never blocks the rest of `DashboardClient` from rendering, matching every other dashboard card's isolation).

**Empty state:** when the sum of `quantidade` across all 7 rows is 0 (fresh install, nobody ever registered), render the same centered empty message as `ClientesPorEtapaChart` ("Nenhum cliente cadastrado ainda.") INSTEAD OF the table — do not render a table full of "—" dashes, matching the existing chart's own empty-state precedent exactly.

**No role-based visual variant:** Vendedor and Supervisor render the exact same `FunilDetalhadoTable` component with no conditional styling — FNL-03 is satisfied entirely by the RPC's RLS scoping (per RESEARCH.md), so this component must never branch on `isSupervisor` for appearance or layout.

### 2. `TempoAteFechamentoCards.tsx` — the FNL-02 KPI pair (2 tiles)

**Layout:** `grid grid-cols-1 gap-4 md:grid-cols-2` — the exact `GanhosPerdidosCards` grid pattern, only `md:grid-cols-3` becomes `md:grid-cols-2` (2 metrics instead of 3). No section heading above the grid — each tile's own label is self-explanatory, matching `GanhosPerdidosCards`'s existing "no redundant section title" convention.

**Tile 1 — "Média de dias até ganho":**
- `Card className="border-l-4 border-l-green-600"` (identical to `GanhosPerdidosCards`'s "Ganhos" tile border)
- Icon: `TrendingUp` (`size-4 text-muted-foreground`), same as "Ganhos"
- Label: "Média de dias até ganho" at `text-sm font-semibold text-muted-foreground`
- Value: `"{N} dias"` at `text-[36px] leading-[1.1] font-semibold text-foreground`, or "—" if the RPC returns no `ganho` row yet

**Tile 2 — "Média de dias até perdido":**
- `Card className="border-l-4 border-l-destructive"` (identical to `GanhosPerdidosCards`'s "Perdidos" tile border — reuses the established "loss metric uses destructive token" precedent, not a new destructive-action usage)
- Icon: `TrendingDown` (`size-4 text-muted-foreground`), same as "Perdidos"
- Label: "Média de dias até perdido"
- Value: `"{N} dias"` or "—"

**Loading state:** `Skeleton className="h-[140px] w-full"` × 2 tiles, in the same 2-column grid — verbatim reuse of `GanhosPerdidosCards`'s per-tile skeleton height.

**Error state:** identical single-`Card` centered error structure to `GanhosPerdidosCards`'s error branch (same copy, same "Tentar novamente" button), independent `FetchState`/`reloadKey` from `FunilDetalhadoTable` — a failure in one new component must never blank the other.

**No role-based visual variant:** same as §1 — FNL-03 is RLS-only, no `isSupervisor` branching in this component's appearance.

### 3. Placement in `DashboardClient.tsx`

Insert `FunilDetalhadoTable` and `TempoAteFechamentoCards` as a new consecutive block immediately after `ClientesPorEtapaChart` and before `GanhosPerdidosCards` in the existing `flex flex-col gap-6` stack — both new components take zero period parameters (per RESEARCH.md's explicit anti-pattern note: "no period-filter parameter"), making them un-period-filtered "live/whole-history" snapshots exactly like `ClientesPorEtapaChart` (D-08's existing grouping logic: un-period-filtered sections stay adjacent, before the period-filtered `PeriodoFilter`-driven sections). Order within the new block: `FunilDetalhadoTable` first (the detailed per-stage table), `TempoAteFechamentoCards` second (the 2 summary tiles) — table-then-summary mirrors how `ClientesPorEtapaChart` (detail) already precedes `GanhosPerdidosCards` (summary) today.
