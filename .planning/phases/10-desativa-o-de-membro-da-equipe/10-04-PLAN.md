Create `lib/equipe/erros.ts` — a pure module with no imports at all. It exports:

  - `type DesativarMembroErrorCode`, a union of exactly these eight string literals: `"unauthenticated"`, `"forbidden"`, `"self_deactivation"`, `"last_supervisor"`, `"invalid_substitute"`, `"rpc_failed"`, `"ban_failed"`, `"generic"`.
  - `type DesativarMembroResult`, the discriminated union from `10-PATTERNS.md`: either `{ data: { clientesReatribuidos: number }; error?: undefined }` or `{ data?: undefined; error: { code: DesativarMembroErrorCode; message?: string } }`.
  - `function mapRpcErrorToCode(message: string | null | undefined): DesativarMembroErrorCode`.

`mapRpcErrorToCode` matches on distinctive fragments of the Postgres exception text, in this order, returning on the first match: `a própria conta` returns `"self_deactivation"`; `último Supervisor ativo` returns `"last_supervisor"`; `substituto inválido` returns `"invalid_substitute"`; `Somente supervisores` returns `"forbidden"`. Anything else — including a null or undefined message, and including `Membro não encontrado`, which has no dedicated message in the Copywriting Contract — returns `"rpc_failed"`.

Two things to write down in the file's header comment. First, why this module exists separately from the Server Action: `"use server"` files may only export async functions, so a synchronous mapper cannot live there; and keeping it dependency-free lets the dialog component import the type without pulling `next/headers` into the client bundle — the same reason `lib/clientes/completude.ts` was extracted. Second, why the codes extend `10-PATTERNS.md`'s five-member union with three more: the UI-SPEC's Copywriting Contract requires four distinct error messages for four distinct causes, and doing the Postgres-text matching here, once, keeps that string coupling out of the React component entirely.

Assert each of the four mapped fragments returns its code, using the FULL exception strings the migration actually raises (not just the fragment), so the test would fail if the migration's wording drifted away from the fragment. Assert `Membro não encontrado`, an unrelated string, `null`, and `undefined` all return `"rpc_failed"`. Assert the ordering property that matters: a message containing `Somente supervisores podem desativar membros da equipe` returns `"forbidden"` and not `"rpc_failed"`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> Server Action | `profileId` and `novoResponsavelId` arrive from a Client Component and are untrusted |
| Server Action -> service_role client | This process now holds a key that bypasses RLS on every table |
| Next.js server bundle -> browser bundle | Anything transitively imported by a Client Component ships to the browser |
| Server Action -> GoTrue | A second service, outside the Postgres transaction |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-04 | Information Disclosure | `SUPABASE_SERVICE_ROLE_KEY` in the Next.js process | critical | mitigate | Read only inside `lib/supabase/admin.ts`, under a non-public env name so Next.js cannot inline it; that module is imported exclusively by the `"use server"` file `app/actions/equipe.ts`; verified by the acceptance-criteria grep and by plan 10-05's import discipline |
| T-10-05 | Elevation of Privilege | `desativarMembroEquipe` callable by any authenticated user (Server Actions are public endpoints) | critical | mitigate | Authorization is the RPC's `is_supervisor()` first statement, not this layer; a Vendedor invoking the action directly gets the `forbidden` mapping and no write occurs (proven by 10-01's Task 3 and 10-03's tests) |
| T-10-12 | Repudiation | silent failure of the Auth ban after a committed RPC | high | mitigate | `ban_failed` is a distinct returned code, never folded into `generic`/`rpc_failed`; the UI-SPEC's partial-failure copy tells the Supervisor exactly which half succeeded |
| T-10-19 | Tampering | `p_novo_responsavel_id` supplied by the browser | medium | mitigate | Validated inside the `SECURITY DEFINER` RPC (`ativo = true` existence check), because the definer context removes RLS as a backstop; the action deliberately does not re-implement that check |
| T-10-20 | Information Disclosure | raw Postgres exception text returned to the browser | low | accept | The messages are product-language guard texts written by this project (no schema names, no data), and the UI renders Copywriting-Contract strings keyed off the mapped code rather than the raw text |
