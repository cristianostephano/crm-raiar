<objective>
Prove the two authorization guarantees of this phase against the live database: the team can never be left without an active Supervisor (EQP-02), and a deactivated member loses access on their very next request even though their token is still valid (EQP-03).

This plan writes `tests/equipe/rls-desativar-membro.test.ts`, the file `10-VALIDATION.md` pins three of its five automated commands to. It uses the disposable-member fixture from 10-02 so no shared seed identity is ever deactivated.

One structural finding this plan records rather than hides: because D-01 rejects `p_profile_id = auth.uid()` before the last-Supervisor count runs, and because `is_supervisor()` requires the caller to be an active Supervisor, the count `supervisors active AND id <> target` always includes the caller and therefore never drops below 1. The `Não é possível desativar o último Supervisor ativo` exception in 10-01's migration is genuine defense-in-depth that is unreachable by construction while D-01 stands. EQP-02 is therefore proven as an invariant — "zero active Supervisors is not reachable" — instead of by forcing an exception that the guard ordering makes impossible. This must be written into the test file's header comment and into the plan SUMMARY, not left as tribal knowledge.

Purpose: EQP-03 is the requirement most likely to be believed on faith. A test that signs in, deactivates, and then re-queries with the SAME session is the only thing that distinguishes "we set a flag" from "access actually stopped".
Output: `tests/equipe/rls-desativar-membro.test.ts` with three passing tests matching the exact `-t` filters in `10-VALIDATION.md`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| still-valid JWT -> RLS | The token keeps asserting the same identity after deactivation; only per-request RLS evaluation stops the access |
| `serviceClient()` -> RLS | Service role bypasses every guard under test; using it for the RPC call would make all assertions vacuous |
| test fixtures -> live team list | A fixture Supervisor left deactivated is a real row a real Supervisor would see |

| T-10-16 | Elevation of Privilege | deactivated Supervisor with a live session | critical | mitigate | Test 3 re-queries `is_supervisor()` and attempts a Supervisor-only INSERT on the same unrefreshed client, asserting both are now refused |
| T-10-17 | Denial of Service (self-lockout) | self-deactivation path | medium | mitigate | Test 1 asserts the D-01 rejection AND that the caller's own row is untouched after the rejection |
