- No new exceptions are needed for this phase beyond that one.

## Typography

Reuses the project's existing locked 4-size scale exactly — **do not** reuse the Dashboard's 36px stat-number waiver here; this phase has no comparable big-number/KPI element (per the objective's explicit instruction).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / table cell / helper text | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Label / badge / caption | 12px (`text-xs`) | 400 (regular) for captions, 600 (semibold) for badge text (matches existing `Badge` component default) | 1.4 |
| Heading (card title, column header, step title) | 16px (`text-base`) | 600 (semibold) | 1.2 |
| Display (dialog/sheet title equivalent — the wizard's step name, e.g. "Mapear colunas") | 20px (`text-xl`) | 600 (semibold) | 1.2 |

Two weights total, matching the rest of the app: **400 (regular)** for body/helper copy, **600 (semibold)** for headings, emphasis, and badge labels. No 500/medium weight is introduced by this phase (the sidebar's `font-medium` active-link treatment is pre-existing chrome, not part of this phase's new screens).

## Color

Reuses the locked project palette exactly (blue `--primary`, `oklch(0.546 0.215 262.881)` light / `oklch(0.623 0.188 259.815)` dark) — no new hues introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (white / `oklch(1 0 0)`) | Page background, wizard card surface |
| Secondary (30%) | `--secondary` / `--muted` (`oklch(0.97 0 0)`), plus the existing dark sidebar (`bg-slate-900`, sketch 001 winner B, already shipped in `AppSidebar.tsx`) framing the page | Column headers on the mapping table, muted helper rows, the persistent left sidebar chrome (unchanged, out of this phase's scope) |
| Accent (10%) | `--primary` blue | Reserved for: the step wizard's active-step indicator, the primary CTA button per step ("Selecionar arquivo" trigger / "Continuar" / "Confirmar importação"), and focus rings on interactive controls. **Not** used for row-status badges (see below) — matches `ClienteCard`'s existing rule that category/status badges never use the blue primary. |
| Destructive | `--destructive` (`oklch(0.577 0.245 27.325)`) | The "Erro" row status only, and any hard file-rejection error banner (wrong file type, oversized file, corrupt file) |

**Row-status color reuses the exact 3-color vocabulary already established for kanban task-status left borders (`ClienteCard.tsx`'s `TASK_STATUS_BORDER`)** — do not invent a new status-color system for the review table:

| Review row status | Color | Precedent reused |
|---|---|---|
| OK | `border-l-4 border-l-green-500` | Same green as `taskStatus: "on_time"` |
| Possível duplicado | `border-l-4 border-l-amber-500` | Same amber as `taskStatus: "late"` |
| Erro | `border-l-4 border-l-red-500` (or `border-l-destructive`, visually equivalent) | Same red as `taskStatus: "none"` |

Accent reserved for: wizard step indicator (current step), every step's single primary-action button ("Selecionar arquivo", "Continuar", "Confirmar importação"), "Baixar modelo de planilha" link icon, focus rings. Never for row-status badges, never for the per-row "Importar mesmo assim"/"Pular" controls (those use neutral `outline`/`ghost` button variants, matching the existing `Badge` "never primary blue for status" rule).

## Copywriting Contract

### Step 1 — Upload

| Element | Copy |
|---------|------|
| Screen/step title | Enviar planilha |
| Secondary action (before upload) | Baixar modelo de planilha |
| Dropzone prompt | Arraste o arquivo aqui ou clique para selecionar |
| Accepted formats helper | Aceita arquivos .xlsx ou .csv, até 10 MB |
| File accepted confirmation | {nome do arquivo} selecionado — {N} linhas encontradas |
| Primary CTA | Continuar |
| Remove-file icon button `aria-label` | Remover arquivo |

### Step 2 — Mapeamento de colunas

| Element | Copy |
|---------|------|
| Screen/step title | Mapear colunas |
| Helper copy under title | Associe cada coluna da planilha a um campo do sistema. Colunas que não devem ser importadas podem ficar marcadas como "Não importar". |
| Column-mapping field option (per-column select, always present as an option) | Não importar esta coluna |
| Required-field-missing inline warning (e.g. Responsável column not yet mapped) | O campo "{nome do campo}" é obrigatório e ainda não foi associado a nenhuma coluna. |
| Primary CTA | Continuar |
| Secondary action | Voltar |

### Step 3 — Revisão

| Element | Copy |
|---------|------|
| Screen/step title | Revisar antes de importar |
| Summary line above the table | {N} linhas no total — {ok} OK · {erros} com erro · {duplicados} possíveis duplicados |
| Status badge: OK | OK |
| Status badge: Erro | Erro |
| Status badge: Possível duplicado | Possível duplicado |
| Erro reason examples (per row, shown under/near the badge) | Razão social não informada · Endereço não informado · Responsável não informado · Categoria "{valor}" não existe · Produto "{valor}" não existe |
| Duplicado reason (per row) | Possível duplicado de "{nome do cliente parecido}" |
| Per-row action (duplicado rows only) | Importar mesmo assim / Pular — defaults to **Pular** until the Supervisor explicitly chooses "Importar mesmo assim" (never a silent auto-import default) |
| Erro rows | No action control shown — erro rows are always excluded; only the reason text renders, no button |
| Primary CTA | Confirmar importação |
| Secondary action | Voltar |

### Empty state

| Element | Copy |
|---------|------|
| Empty-state heading (0 rows found under the header) | Nenhuma linha encontrada nesta planilha |
| Empty-state body | Verifique se o arquivo tem dados abaixo da linha de cabeçalho e tente enviar novamente. |

### Error states

| Element | Copy |
|---------|------|
| Wrong file type / extension rejected | Não foi possível ler este arquivo. Envie um arquivo .xlsx ou .csv. |
| File too large | Este arquivo é maior que 10 MB. Reduza o arquivo ou divida em partes menores. |
| Corrupt / unparseable file | Não foi possível ler esta planilha. Verifique se o arquivo não está corrompido e tente enviar novamente. |
| Generic validation failure (server-side) | Não foi possível validar a planilha agora. Tente novamente. |

### Destructive actions

None. This phase never writes to the database (Phase 6's own success criterion #5) and never deletes anything — the per-row "Pular" choice on a duplicado row is a reversible, in-memory decision (the Supervisor can flip it back to "Importar mesmo assim" before the final confirm), not a destructive action requiring a confirmation dialog. The final "Confirmar importação" button is visually part of this phase's Review screen, but the actual write call it triggers belongs to Phase 7 (`confirmarLoteImportacao`) — Phase 6 delivers the button and the reviewed/decided row state; wiring its `onClick` to the write action is explicitly Phase 7 scope (see `ARCHITECTURE.md` Pattern 5).

## Layout & Interaction Notes (Claude's Discretion resolved)

`06-CONTEXT.md` left the exact mapping/review layout to Claude's Discretion — resolved here so planner/executor don't re-decide it:

- **Wizard shell:** a single page (`app/(app)/clientes/importar/page.tsx`, Supervisor-only — redirect to `/` for a Vendedor, same pattern as `app/(app)/configuracoes/page.tsx`) with a simple 3-step, non-interactive numbered indicator at the top ("1 Enviar planilha · 2 Mapear colunas · 3 Revisar"), current step highlighted with `--primary`. Steps are sequential and gated (cannot jump ahead) — this is not a `Tabs` component (steps aren't freely switchable), just a plain styled row of 3 labels.
- **Mapping screen layout:** a list/table, one row per spreadsheet column detected: `[Coluna do arquivo]` (raw header text) · `[Prévia]` (first 2-3 parsed values, `text-sm text-muted-foreground`, truncated) · `[Campo do sistema]` (a `Select`, one option per system field below, plus "Não importar esta coluna" always last). Auto-suggest a best-guess mapping per column by normalized label match against the field list below; the Supervisor can override every row.
- **System field vocabulary for mapping** (target options in the Select): Razão social · CEP · Rua · Número · Complemento · Cidade · Estado · Categoria · Contato · Telefone · Email · Produtos consumidos · Responsável (vendedor) · Número de lojas · Não importar esta coluna. Funil stage is never a mapping target — every imported row always lands in "Aguardando contato" (already decided, removes one column from this list entirely).
- **Review screen layout:** the new `Table` component (shadcn official), client-side paginated at **50 rows per page** (reuse `@tanstack/react-table`, already an approved dependency in `STACK.md` — no new package needed). Each row shows: row number, the mapped field values, the status badge + reason, and (duplicado rows only) the "Importar mesmo assim"/"Pular" toggle as two small `outline`/`ghost` buttons (not a `Select`, so the current choice is always visually obvious without opening anything).
- **Progress feedback during parse/validate:** per Pitfalls A2/A3/A5 UX guidance, show a simple inline step label while each async step runs ("Lendo arquivo…" → "Validando linhas…"), reusing the existing `Skeleton`-based loading pattern already used in `GanhosPerdidosCards`/`ClientesPorEtapaChart`, not a new spinner component.
- **Toast/banner pattern for transient errors:** reuse `KanbanBoard.tsx`'s existing local transient banner pattern (no toast library installed project-wide) — same bottom-centered, auto-dismissing banner, same `role="alert"`/`role="status"` split.
