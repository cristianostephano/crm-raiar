# Phase 28 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Framing note (read this before the tables below):** this phase introduces one genuinely new screen (`/perdidos`) and one new menu entry, but the visual language is deliberately a close cousin of the Agenda screen, not a fresh design (CONTEXT.md D-04). Everything cited from `AgendaSemDiaFixo.tsx`/`AgendaItemRow.tsx`/`ClienteCard.tsx`/`PeriodoFilter.tsx`/`ClienteToolbar.tsx` below is a **reuse citation**, not a new decision — this document only makes NEW, prescriptive calls for the four elements CONTEXT.md/RESEARCH.md left open: (1) the period filter control, (2) the empty state, (3) how "motivo da perda" reads on the row, (4) the "Reabrir" button's exact form and placement. Everything else (row template, spacing, typography, color, RLS-scoped visibility) is inherited verbatim from the Agenda pattern and is cited here only so the checker can confirm nothing drifted.

## Phase-Specific Contract Detail

### 1. Row template (D-04, reused — not a new decision)

One `PerdidosItemRow` per client, built on the same `Card size="sm"` shell as `AgendaSemDiaFixo.tsx`/`AgendaItemRow.tsx` (`CARD_SM_CLASSNAME`, `gap-1.5`, `px-3`/`py-3`). Layout, top to bottom:

1. **`CardHeader`** — two-column grid (`grid-cols-[1fr_auto]`, same shape as `AgendaItemRow.tsx`'s header):
   - Left column: `CardTitle` = `nomeExibicaoCliente(cliente.razaoSocial, cliente.nomeFantasia)`, `"truncate text-base leading-tight font-semibold"` (verbatim class reuse), `title` attribute set to the same string for the native tooltip on truncation.
   - Right column: the **Reabrir button** (see section 4 below) — never a text badge here, this column is action-only on this screen (unlike `AgendaItemRow.tsx`, which puts origin/concluído badges here).
2. **`CardContent`** — `flex flex-col gap-1.5 px-3`, three possible caption lines, all `text-sm text-muted-foreground` (verbatim class reuse from `AgendaSemDiaFixo.tsx`):
   - Line 1 (always): motivo da perda — bare text, no "Motivo:" prefix (matches this codebase's existing bare-caption convention, e.g. `AgendaSemDiaFixo.tsx`'s `MOTIVO_SEM_DIA_FIXO_LABELS[...]` line).
   - Line 2 (always): `` `Perdido em ${format(parseISO(perdidoEm), "dd/MM/yyyy")}` `` — **this line takes an explicit verb prefix** ("Perdido em"), unlike `AgendaItemRow.tsx`'s bare date, because this row already has a motivo caption directly above it; an unprefixed date here reads ambiguously (motivo date? creation date?) in a way `AgendaItemRow.tsx`'s single-caption context does not. Date parsed via `parseISO`, never `new Date(string)` (project-wide rule, `lib/agenda/itens.ts`'s documented timezone bug).
   - Line 3 (conditional, `showResponsavel && responsavelNome`): bare vendedor name — same truncation class (`truncate text-sm text-muted-foreground`) as `AgendaSemDiaFixo.tsx`'s own responsável line.

### 2. Reabrir button (NEW decision — D-04 said "same size/format as ClienteCard's quick-action buttons," this section makes that literal)

- **Form:** icon-only, `size-11` (44px touch target), same shared class string as `ClienteCard.tsx`'s `QuickActionButton`/`EtapaArrowButton`: `"flex size-11 shrink-0 items-center justify-center rounded-md transition-colors text-muted-foreground hover:bg-muted hover:text-foreground"`. **Never** a `variant="outline"` labeled text button (that shape is reserved for `AgendaItemRow.tsx`'s "Concluir" — a different, non-instant action) — D-04 explicitly calls for the icon-quick-action shape, not the outlined-text-button shape.
- **Icon:** `RotateCcw` (`lucide-react`) — a counter-clockwise undo arrow, semantically "reverse the previous action" (being marked perdido). Not currently imported anywhere in `components/`, so no visual collision with any icon already in use on this or adjacent screens.
- **Visible label:** none (icon-only, matching the quick-action-icon convention) — but native `title={label}` attribute set (same pattern as `EtapaArrowButton`, not a Radix `Tooltip`) so a mouse user gets an on-hover text hint reading "Reabrir".
- **Accessible name:** `aria-label` = `` `Reabrir ${nomeExibicaoCliente(...)}` `` (see Copywriting Contract) — carries client identity for screen-reader users, since row position alone isn't available to them.
- **Interaction (D-05, locked):** `onClick` calls `marcarStatus(clienteId, "em_andamento")` directly — **no confirmation dialog**, applies instantly, same `event.stopPropagation()` defensive pattern already used by every other in-row action button in this codebase (`QuickActionButton`, `EtapaArrowButton`) so a click never bubbles into a row-level `onOpen` if one is ever added later.
- **Placement:** `CardHeader`'s right (`auto`) grid column, vertically aligned with the card title — never in `CardContent` (D-04's "action row" framing distinguishes this from `AgendaItemRow.tsx`'s bottom-right "Concluir" placement, which is a full-width-row second citizen; Reabrir is a one-touch peer action next to identity, not a follow-up step after reading the row).
- **No loading spinner variant needed:** the action either succeeds (row disappears per D-09, no code needed — reloadKey refetch) or fails (row stays, a transient error surfaces via the same banner pattern `KanbanBoard.tsx` already uses for failed mutations — not a new pattern, cited for completeness only).

### 3. Period filter (NEW decision — resolves the "Claude's Discretion" item on filter UI style and default window)

- **Component shape:** structurally and visually identical to `components/dashboard/PeriodoFilter.tsx` — same `Select` + conditional `Popover`+`Calendar mode="range"` composition, same "Aplicar período"/"Cancelar" footer, same `<span className="text-sm font-semibold">Período</span>` label, same `w-fit` trigger sizing. This is a **new, phase-local component** (`PerdidosPeriodoFilter.tsx`), not a prop-reuse of the dashboard one — the preset set differs (below) and dashboard's `PeriodoPreset` type is dashboard-specific.
- **Preset list (replaces dashboard's `30dias`/`este_mes`/`este_ano`/`personalizado`):**

  | Value | Label | Default |
  |-------|-------|---------|
  | `tudo` | "Tudo" | **Yes — selected on first load** |
  | `30dias` | "Últimos 30 dias" | No |
  | `90dias` | "Últimos 90 dias" | No |
  | `personalizado` | "Personalizado" | No |

  Rationale (resolves RESEARCH.md's A2/D-11 discretion item explicitly, as a prescriptive decision rather than leaving it open): this list only ever grows (nothing removes a client from "ever having been perdido" — RESEARCH.md Pitfall 2) and D-02 already established this screen is a report/archive, not an urgent action queue — defaulting to a restrictive 30-day window would hide most of the list's real value on first visit. "Tudo" as default satisfies PERD-04 (a period filter exists and works) without contradicting the "not urgent, no alarm" tone D-02 sets. Dashboard's "Este mês"/"Este ano" calendar-boundary presets are dropped in favor of "Últimos 90 dias" — a rolling window fits "when was this client lost" better than a calendar-month/year boundary for a list this open-ended.
- **Placement on page:** directly below the page `<h1>`, above the search input and the row list — same vertical order as `AgendaList.tsx` places its own filter bar (title → filters → list).
- **Search-by-name (NEW decision, resolves the other open discretion item — "se tem busca por nome também"):** **Yes.** A single `Input` with a leading `Search` icon, placed to the left of (or above, on narrow viewports — `flex flex-wrap`) the period `Select`, in a shared container: `<div className="flex flex-col gap-3 rounded-lg bg-secondary p-3">` (verbatim reuse of `ClienteToolbar.tsx`'s filter-bar container class). Client-side substring filter over the already-fetched page's rows (same "filter what's loaded, don't add a second query" precedent as `KanbanBoard.tsx`'s existing search/filter — RESEARCH.md's Pitfall 7 equivalent). Search state does **not** persist across a period-filter change; both can be active simultaneously (search narrows within whatever the period filter already returned).

### 4. Empty state (NEW decision)

Two distinct copy branches (see Copywriting Contract), selected by a single boolean the page already has for free (`preset !== "tudo"` OR a custom range is applied):

- **True empty (preset = "tudo", zero perdidos ever):** heading + body rendered inside a centered, muted block — no icon, no illustration (matches this codebase's minimal empty-state convention; no empty-state illustration exists anywhere else in the app to be consistent with). Typography: heading `text-sm font-semibold`, body `text-sm text-muted-foreground` directly below it, both centered, inside `py-12` vertical padding to give the empty page visual weight without inventing a new spacing token (`py-12` = 48px = the already-declared `2xl` spacing token).
- **Filtered-to-empty (a narrower preset/range returns zero rows, but "Tudo" would not):** same visual shell, different copy, plus the body text explicitly names the escape hatch ("...selecione \"Tudo\"...") so the vendedor isn't stuck wondering if the feature is broken.
- Unlike `AgendaSemDiaFixo.tsx`'s "render nothing at all" convention (appropriate there because that section is a reminder, and an empty reminder is noise) — this screen **is** the entire page content, so a silent blank page would read as broken, not as "nothing to remind you of." The empty state here always renders something.
