# Phase 31 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase builds a brand-new, isolated screen ("Agenda 2") that must NOT modify `/agenda`, `AgendaList.tsx`, `AgendaItemRow.tsx`, or any existing `AppSidebar.tsx` entry. Every visual rule below either (a) mirrors an existing pattern byte-for-byte (cited with its source file) so Agenda 2 reads as "the same product," or (b) is a genuinely new treatment introduced by this phase (called out explicitly as NEW). Sibling components only — `Agenda2List.tsx`, `Agenda2ItemRow.tsx`, `Agenda2ItemForm.tsx` — same "sibling module, not shared abstraction" precedent already used between Perdidos/Encerrados.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps inside badges/buttons |
| sm | 8px | Compact element spacing (e.g. date + atraso icon row) |
| md | 16px | Default element spacing (form field stacking, `gap-4`) |
| lg | 24px | Section padding (`gap-6` between page header / list body) |
| xl | 32px | Layout gaps (not expected to be needed at this phase's single-column layout) |
| 2xl | 48px | Major section breaks (not expected this phase) |
| 3xl | 64px | Page-level spacing — empty state vertical padding (`py-16`) |

**Exceptions:**
- `gap-1.5` (6px, half-step) inside `Agenda2ItemRow`'s `Card`/`CardHeader`/`CardContent` — carried over unchanged from `AgendaItemRow.tsx` (`components/agenda/AgendaItemRow.tsx` line 107/143), which already establishes this exact half-step as the tight-card-row precedent. Do not invent a second half-step value.

## Component Contracts

These sections exist because the template's generic fields can't fully capture the two genuinely NEW interaction patterns this phase introduces (D-04/D-06 strikethrough+editable, D-07 duplicate warning). Executor and checker should treat this section as load-bearing, same weight as the tables above.

### `Agenda2ItemRow` — pendente vs. concluído (D-04/D-05/D-06)

Structure mirrors `AgendaItemRow.tsx` (`Card size="sm"` → `CardHeader` grid `[1fr_auto]` → `CardContent` flex column), with these deltas:

| State | Card | Title (nome do cliente) | Badges | Actions row |
|-------|------|--------------------------|--------|-------------|
| Pendente, no prazo | Full opacity, no left border | `text-base font-semibold`, no strikethrough | none | `Editar` (ghost) + `Apagar` (ghost, destructive text) on the left; `Concluir` (outline) on the right |
| Pendente, atrasado | `border-l-4 border-l-red-500` | same as above | `TriangleAlert` tooltip next to the date (unchanged from `AgendaItemRow`) | same as above |
| **Concluído (NEW, D-04)** | **Full opacity — no `opacity-60` dimming** (deliberate divergence from `AgendaItemRow`'s `opacity-60`: since D-06 requires the item to stay fully editable, dimming the whole card would visually contradict that it's still actionable) | `text-muted-foreground line-through` | outline `Badge` "Concluído" (`CheckCircle2`, `border-emerald-600 text-emerald-600`) — same badge as `AgendaItemRow` | `Editar` (ghost) + `Apagar` (ghost, destructive text) — **unchanged, never hidden**; `Desmarcar` (outline, `RotateCcw`) replaces `Concluir` on the right |

Rules that must hold regardless of state:
- The atraso red border/triangle NEVER renders when `concluido === true` (`mostraAtraso = atrasado && !concluido`, same guard as `AgendaItemRow.tsx` line 90).
- `Editar` is rendered in every state — the only per-state swap is `Concluir` ↔ `Desmarcar`. This is the opposite of the historical `AgendaItemRow` bug risk flagged in RESEARCH.md Pitfall 5 — do not copy the `concluido ? null : <Button>` conditional onto the Editar button.
- Clicking `Editar` opens `Agenda2ItemForm` in edit mode, pre-filled, regardless of `concluido`.

### `Agenda2ItemForm` — create/edit Dialog with duplicate warning (D-07, AGD2-01/03)

Mirrors `ClienteQuickCreateForm.tsx`'s Dialog + react-hook-form + zod shape:

- Trigger: `Button` "Adicionar visita" (`Plus` icon) opens the Dialog in create mode. `Editar` on a row opens the same Dialog pre-filled in edit mode (title changes to "Editar item").
- Fields, in order:
  1. **Nome do cliente** (`Input`, required) — `FormDescription` LGPD hint directly below (see Copywriting Contract)
  2. **Bairro** (`Input`, required)
  3. **Data** (`Popover` + `Calendar mode="single"`, same pattern as `ConcluirItemDialog.tsx` lines 292–303 — trigger shows `dd/MM/yyyy` or placeholder "Selecionar data"; **no disabled dates** — D-09 explicitly allows past dates)
- Duplicate check (D-07): client-side only, evaluated on submit against the already-loaded item list (same vendedor, case-insensitive trimmed name match + same date). No extra Server Action, no extra round-trip (RESEARCH.md Architecture Patterns, "Aviso de possível duplicado").
  - First submit with a match found: form does NOT submit. Show the amber warning banner (Copywriting Contract) above the submit button. Submit button label switches from "Adicionar visita"/"Salvar alterações" to "Criar mesmo assim".
  - Second submit (button now reads "Criar mesmo assim"): proceeds normally, calls the Server Action.
  - Editing any of the three fields after the warning appears clears the warning and reverts the button label.
- Error/success banners: same `role="alert"` destructive banner and `role="status"` primary-tinted success banner slots as `ClienteQuickCreateForm.tsx` lines 158–174 — reused pattern, not a new visual.

### Empty state (D-10)

Layout mirrors `AgendaList.tsx`'s existing empty-state block (`flex flex-col items-center gap-1 py-16 text-center`) with one addition — a CTA button, which `AgendaList.tsx`'s own empty state does NOT have (intentional divergence: Agenda 2 items are always manually created, so the empty state must not be a dead end):

```
flex flex-col items-center gap-1 py-16 text-center
  <p class="text-base font-semibold">Sua Agenda 2 está vazia</p>
  <p class="text-sm text-muted-foreground">Anote aqui quem você vai visitar em cada dia — nome do cliente, bairro e data.</p>
  <Button class="mt-4"><Plus/>Adicionar visita</Button>
```

Only rendered for the vendedor's own empty agenda. Supervisor viewing a vendedor filter with zero items sees the vendor-filtered empty state copy instead (no CTA — D-16, Supervisor never creates).

### Menu entry (AGD2-06, D-12–D-15)

- Insert into `PRINCIPAL_SECTION.links` in `AppSidebar.tsx`, immediately after `/agenda` and before `/clientes` (final order: Agenda → Agenda 2 → Clientes → Perdidos → Encerrados → Dashboard).
- Icon: **`NotebookPen`** (lucide-react, already available, zero new import cost) — visually distinct from `ListChecks` (Agenda), `Users`, `Archive`, `PauseCircle`, `LayoutDashboard`. Rationale: "handwritten note" reads closer to "anota à mão" than a generic clipboard icon. `ClipboardList` is the acceptable fallback if the project owner prefers it.
- Badge count and compact-mode dot: **byte-for-byte the same treatment** already used for `/agenda`'s `badgeCount`/`data-slot="agenda-pendente-dot"` (D-12/D-14) — same `Badge` classes (`h-4 min-w-4 shrink-0 px-1 text-[10px]`), same dot classes (`absolute -top-0.5 -right-0.5 size-2.5 rounded-full bg-primary ring-2 ring-slate-900`). Do not restyle.
- Count source: a **second**, independent count (`agenda2Count`), never merged with `agendaCount`. Per Pitfall 2/3 of RESEARCH.md, the count query must explicitly filter `.eq("vendedor_id", user.id).eq("concluido", false)` in code — the RLS SELECT policy alone is not sufficient to keep a Supervisor's badge scoped to zero.
