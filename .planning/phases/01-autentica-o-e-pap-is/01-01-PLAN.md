## Phase Goal (MVP user story)

**As a** sales-team member, **I want to** log in securely with my Supervisor or Vendedor role recognized system-wide, **so that** the database itself controls what I can see — starting at the data layer, not the screen.

## This plan

Lay the walking-skeleton tooling foundation: confirm the Supabase project credentials in `.env.local` are real and present, install the locked auth/SSR/form dependencies, add the shadcn primitives the auth screens need, and stand up the Vitest + Playwright test runners with a shared "authenticate as a seeded user" helper that every later RLS test reuses.

Purpose: Nothing else in the phase (migration, login, invite, reset) can be built or verified until the SDK is installed, the credentials are confirmed reachable, and there is a way to run tests against real RLS. This is the scaffold half of the walking skeleton.
Output: Updated `package.json`, five shadcn UI primitives, `vitest.config.ts`, `playwright.config.ts`, `supabase/config.toml` (from `supabase init`), and `tests/helpers/supabase-test-clients.ts`.
